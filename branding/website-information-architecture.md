# RexTexh Website Information Architecture — Initial Draft

## Purpose of this document
This document defines how the RexTexh website should be structured so the brand communicates clearly, converts the right audiences, and supports the broader ecosystem without feeling cluttered.

This is not just a sitemap.
It is the strategic page architecture that translates:
- positioning
- audience hierarchy
- messaging order
- offer structure

into a coherent website experience.

---

## 1. Strategic conclusion
The RexTexh website should be structured as a **credibility-first business website with ecosystem pathways**.

That means:
- the main site should speak to business buyers first
- the offer structure should be clear and commercially legible
- proof and trust should be integrated naturally
- education should have a meaningful home without dominating the business story
- conversion should feel easy, direct, and non-pushy

The website should not feel like:
- a creator website
- a general agency website
- a course platform first
- a flat service directory

It should feel like:
- an AI-first implementation company
- built by someone who teaches and ships
- commercially clear
- premium but accessible
- structured for both trust and conversion

---

## 2. Core architecture principle
The website should follow this hierarchy:

1. **Homepage = business-first overview and conversion hub**
2. **Services / offers = clear commercial detail**
3. **Proof / insights = trust-building layer**
4. **Learning hub = education ecosystem layer**
5. **About / Rex connection = human trust layer**
6. **Contact / booking = conversion layer**

This allows the website to behave like a real business platform while still leveraging your public teaching identity.

---

## 3. Recommended top-level navigation
The cleanest top-level navigation is likely:

- Home
- Services
- Solutions or Work
- Learn
- About
- Contact

Alternative naming options:
- **Solutions** instead of **Services** if you want a more modern, business-outcome framing
- **Insights** or **Resources** as a bridge between proof content and learning content
- **Work** or **Case Studies** if proof becomes strong enough early

Locked first-version page set approved by Rex:

- **Home**
- **Services**
- **Learn**
- **About**
- **Book a Call**

with proof/work content integrated either:
- inside Home and Services at first
- or later expanded into a dedicated **Work** / **Case Studies** section

Reason:
This keeps the first version simple while leaving room for ecosystem growth. `Book a Call` replaces a generic `Contact` label because the primary conversion action should feel direct, commercial, and low-friction.

- establish category

- build trust

- make the business category clear immediately

Core direction:
- practical AI implementation for businesses

Primary CTA:
- Book a consultation

Secondary CTA:
- Explore services
or
- Learn how we work

Purpose:
- quickly show what RexTexh actually offers

Suggested blocks:
- AI implementation consulting

- internal assistants / agent systems
- advisory / training support

Purpose:
- show why this brand is credible
- reinforce the builder + teacher positioning

Suggested proof types:
- public teaching
- practical implementation thinking

#### 4. Who it is for
Purpose:
- make the audience segmentation visible without overcomplicating the site

#### 6. About / founder bridge

#### 7. Conversion section
Purpose:

Suggested paths:

#### 8. Footer architecture

## 5. Services section architecture
This is the main commercial depth area.

### Goal of the Services section
- turn homepage clarity into concrete offer understanding
- help the primary audience quickly identify fit
- create a path from curiosity to inquiry

### Recommended structure
A main **Services** page that introduces the overall offer architecture, supported by detail pages or anchored sections.

#### Main Services page
Should explain:
- the overall implementation philosophy
- who the services are for
- the major offer categories
- how to engage

#### Recommended service categories
1. AI implementation consulting
2. custom AI software and product builds
3. automation and workflow systems
4. internal assistants / agent systems
5. advisory and training support

Depending on how streamlined you want the site, these can be:
- separate pages
- one strong services page with detailed sections
- a hybrid model where the main service families are separate but supporting offers are grouped

### Best initial recommendation
Start with:
- one strong **Services** page
- optional supporting pages for the core business offer families

This avoids overbuilding the site too early.

## 6. Proof / work architecture
RexTexh needs visible trust, but not necessarily a giant case-study library on day one.

### Short-term recommendation
Integrate proof directly into:
- homepage
- services page
- about page
- learning content

### Longer-term recommendation
Add a dedicated area such as:
- Work
- Case Studies
- Proof
- Insights

### What belongs in this layer
- selected project outcomes
- implementation breakdowns
- practical articles
- build stories
- selected tutorial-to-real-world bridges
- credibility signals from public content

### Strategic note
Because proof may develop over time, this area should be designed to scale.
At first, it may be lightweight.
Later, it can become one of the strongest brand assets.

## 9. Contact / conversion architecture
The site should make it easy to take action without feeling pushy.

### Main conversion page
A dedicated **Contact** or **Book a Call** page should exist.

### Core purposes
- direct business inquiries
- route people to the right type of engagement
- reduce friction around next steps

### Suggested pathways
- business consultation
- project inquiry
- strategic advisory inquiry
- mentoring inquiry
- corporate training inquiry

### Important principle
Do not force every visitor into one generic form.
The site should acknowledge that different users are arriving with different needs.

A simple routing approach is stronger:
- I want help implementing AI in my business
- I want to discuss a software / automation build
- I want training for my team
- I want mentoring or guidance

## 11. Audience journeys through the site

### Journey A — Business buyer
Likely flow:
- Home
- Services
- proof on page / About
- Contact / Book a consultation

Key requirement:
This journey should feel direct and credible.

### Journey B — Team / organizational buyer
Likely flow:
- Home
- Services
- training/advisory section
- Contact / training inquiry

Key requirement:
This journey should show business relevance and practical capability.

### Journey C — Learner / builder
Likely flow:
- public content
- Learn page
- mentoring or structured path
- optional crossover into About / Services

Key requirement:
This journey should feel structured, not random.

---

## 12. Key IA principles to protect

### Principle 1 — Business-first architecture
Even though the ecosystem is broad, the website should still feel like a serious implementation company first.

### Principle 2 — Education has a home, not the homepage crown
Learning should be visible and meaningful, but not overpower the commercial center.

### Principle 3 — Proof should be embedded everywhere
Trust should not live only on one page.
It should appear across homepage, services, about, and learn.

### Principle 4 — The founder relationship must be clarified
The website should make it obvious how Rex, Prompt-to-Code with Rex, and RexTexh relate.

### Principle 5 — Conversion should be multi-path
Different audiences need different next steps.
A single generic CTA is weaker than guided pathways.

---

## 13. What the website should avoid
To preserve clarity, the IA should avoid:

- too many top-level nav items too early
- mixing business services and learning content with equal emphasis in the hero
- hiding core offers beneath too much storytelling
- making the site feel like a portfolio first and a company second
- presenting a random blog without structured learning organization
- making Contact the only place where offer distinctions become clear
